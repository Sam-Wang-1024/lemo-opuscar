# Editable films (this fork): the Studio film editor contract

In this fork every film is made so the **Mochi Studio film editor** (Video Editor → Films) can open it, show
any frame, edit it and rebuild it. The editor never touches pixels: it edits the film's **data** and re-runs the
film's own pipeline. That only works if the film keeps every editable value in one data file and says how to
build itself. Follow this from the first line of code; retrofitting it later means rewriting the page.

Worked example: [`films/first-time-machine/`](films/first-time-machine/).

## 1. Scaffold first

```sh
sh ext/studio/new-film.sh <name> [--lang en|zh] [--fps 24] [--title "…"] [--style <slug>]
```

It writes (never overwriting) `timeline.js`, `film.data.json`, `studio.json` and `tools/` (`sync.mjs`,
`export.mjs`, `frames.mjs`, `assets.sh`) into `films/<name>/`. Then write the page, `mix.py` and `build.sh`
against them, as below. Everything else in AGENTS.md / DIRECTOR.md / TECHNIQUE.md is unchanged.

## 2. `film.data.json` — the only place editable values live

| Key | What | Who reads it |
|---|---|---|
| `title`, `style`, `fps`, `bpm`, `dur` | film basics (`dur` in seconds) | everything |
| `hit` | `{name: seconds}` — every key moment the picture is timed from (camera keys, landings, cuts, lit lines, card in/out) | the page (via `timeline.js`), `mix.py` (via `out/timeline.json`) |
| `voice` | `[{id, t, text, voice, speed, asr?}]` — narration lines, `t` = start in seconds, `text` as spoken (numbers spelled out) | `tools/sync.mjs` → `voice/lines.json` → TTS; `export.mjs`; `mix.py` |
| `subs` | `[{id, line, en, zh?, from?}]` — one subtitle line per cue; `from` = the spoken word a split cue starts on | `export.mjs` → `out/cues.json` (the page draws these) + `.srt` |
| `texts` | `{card: [row, …]}` — **every word the page draws** on cards, labels, tags, index, end card | the page |
| `mix` | `{music, foley, beds, voice: dB, mute: {stem: bool}}` | `mix.py` |
| `sections` | `[{label, from, to}]` — `from`/`to` are seconds, a `hit` name, or `"end"`; labels the timeline only | the editor |

Rules:
- **No hard-coded times, narration or on-screen words** in the page or `mix.py`. A time is `HIT.x` (or
  `HIT.x + offset`), a word is `TX.card[row]`. Derived numbers (a counter rolling 1895 → 1887) may stay in code.
- Key moments in `hit` must stay in **increasing order along the film**: the editor lets a key move only
  between its neighbours, and camera tracks need monotone keys.
- `voice[].text` is what the TTS speaks; subtitles carry the written form (digits, accents).

## 3. The page

- Import from `./timeline.js` (top-level `await` loads `film.data.json` in both the browser and Node):
  `import { HIT, DUR, TX } from './timeline.js'` — don't copy values out of it at build time.
- Load `out/cues.json` for subtitles (optional at load: it may be missing before the first `cues` step).
- `window.TEXTS(t)` must report every text it draws with `{id, key, text, x0, y0, x1, y1}`, where **`key` =
  `"<card>.<row>"`** for texts that come from `TX` (code-drawn texts like counters have no `key`). The editor
  uses `key` to make a text editable in place; `readcheck.mjs` ignores the extra field.
- Support `?nosubs=1` (frame exports and the editor's text probe use it).
- Same page contract as TECHNIQUE.md §2 otherwise (`DUR`, deterministic `render(t)`, `READY`, `EV`).

## 4. `mix.py`, voice and the build

- `mix.py` reads `out/timeline.json` and `events.json`, places each line at `voice[].t`, writes
  **`out/stems/{music,foley,beds,voice}.wav`** and `out/mix.wav`, and applies `film.data.json → mix` (dB and
  mute per stem) before summing. The editor plays these stems for its live preview mix.
- Voice goes through `tools/sync.mjs` (data → `voice/lines.json`) before `core/tts/tts.py`/`tts_zh.py`; never
  edit `voice/lines.json` by hand.
- `tools/assets.sh` downloads and prepares whatever git doesn't hold (scans, footage, data), idempotently. The
  editor runs it as the first step of a full build, so a fresh clone builds from the editor alone.
- `build.sh` calls the same tools in the same order as `studio.json`'s `order` (assets → voice → cues → events
  → mix → video → master → readcheck), so the command line and the editor build the same film.
- A page with self-hosted subset fonts adds a `fonts` step (its `tools/fonts.py` must read `film.data.json`
  too, so edited texts get their glyphs) and lists it first under `depends.texts`.

## 5. `studio.json`

Generated by the scaffold; edit it when the film needs another step. `steps` are argv lists run from the
library root with `$PY` (library `.venv` Python), `$NODE`, `$FILM` (the film folder) and `$LIB` substituted;
`order` is the full build; `depends` maps each `film.data.json` key to the steps a change to it needs (the
editor's "rebuild what changed" runs exactly those). `voice_time` = a narration line moved without new wording
(no TTS). `output` names the mastered mp4; `stems` and `voice_dir` are what the editor plays.

## 6. Before delivering

On top of DIRECTOR.md §11:
- `node tools/export.mjs films/<name>` exits 0, and a still from `core/render/still.mjs` looks the same after
  any refactor.
- Change one text in `film.data.json` → the still shows it; move one `hit` → the picture follows. Undo both.
- `git add films/<name>` commits the source only: this fork's `.gitignore` keeps renders, downloads, voice,
  fonts, frames and versions local (`build.sh`/`assets.sh` regenerate them).
- Tell the user the film is in Mochi Studio → Video Editor → Films (it lists every folder with a `studio.json`).
